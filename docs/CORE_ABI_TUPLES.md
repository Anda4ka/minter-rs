# ABI: кортежи и рекурсивный энкодер (Phase D — завершение #10 ABI)

Финальный шаг ABI‑части пункта **#10**: поддержка кортежей `(T1,T2,...)` — в т.ч.
статических, динамических и с вложенными массивами/кортежами. Заодно энкодер
переписан на **единое рекурсивное ядро**.

## Background

Кортеж в ABI кодируется как «аргументы функции без селектора»: голова (со
смещениями для динамических компонентов) + хвост. Кортеж **динамический**, если
хоть один компонент динамический; иначе **статический** (все компоненты инлайн).
Это ровно та же логика, что и у списка аргументов функции — отсюда унификация.

## Intuition

Одна рекурсивная функция кодирует любую «последовательность (тип, значение)»:

```
encode_sequence(types, values):
  head_size = Σ type_head_bytes(t)
  для каждого (t, v):
    если dynamic(t):  head += offset(head_size + |tail|);  tail += encode_dynamic_value
    иначе:            head += encode_static_value
  return head ++ tail
```

Кортеж — это `encode_sequence` над его компонентами; массив статических
элементов, `bytes[]`, `bytes`, скаляр — листья рекурсии. `build_calldata` теперь
= `selector ++ encode_sequence(arg_types, arg_values)`.

Игрушечный пример `f((uint256,bytes))` со значением `(7,0x1122)`:

```
[offset=0x20]           # аргумент-кортеж динамический
  [7]                   # uint (инлайн в голове кортежа)
  [offset=0x40]         # смещение к bytes внутри кортежа
  [len=2][1122…]        # хвост кортежа
```

## Code (`abi.rs`)

- `parse_tuple_components` + `split_top_level` (деление по запятым на глубине 0,
  учитывая `()` и `[]`) + `split_tuple_values` (для значений `(v1,v2,…)`).
- Корректный рекурсивный `type_is_dynamic` (статический кортеж/фикс‑массив больше
  не считаются динамическими) и `type_head_bytes`.
- `encode_static_value` / `encode_dynamic_value` / `encode_sequence` — общее ядро.
- `build_calldata` и `encode_parameter` теперь делегируют в это ядро; вывод для
  ранее поддержанных типов **не изменился** (подтверждено golden‑тестами).
- `is_supported_type` рекурсивно принимает кортежи; понятные ошибки для
  массивов кортежей (`(uint256)[]`), вложенных массивов, фикс‑массивов
  динамических элементов и невалидного значения кортежа.

> **Границы:** массивы кортежей (`T[]` где T — tuple) пока не поддержаны — дают
> внятную ошибку. Это редкий случай для mint‑вызовов.

## Verification

`cargo test -p minter-core` → **162 passed** (+4). Golden‑тесты: статический
кортеж инлайн, динамический кортеж с `bytes` (offset 0x20/0x40), смешанный
`f(uint256,(address,uint256))`, кортеж с массивом `claim((address,bytes32[]))`,
и понятные ошибки. **Все прежние ABI‑тесты (transfer, массивы A/B/C, string,
bytes) зелёные** — рекурсивный рефактор поведение не изменил.

## Alternatives

| Подход | Против |
|---|---|
| alloy `DynSolValue` | тяжёлая зависимость; свой ввод «строки оператора» |
| Оставить кортежи неподдержанными | часть claim/permit‑контрактов принимает структуры |
| Не унифицировать (спец‑ветки на кортеж) | дублирование логики head/tail, выше риск ошибок |

## Quiz

<details>
<summary>1. Когда кортеж статический?</summary>

- **A. (верно)** Когда **все** компоненты статические — тогда он весь инлайн в
  голове, без offset.
- **B.** Всегда.
- **C.** Когда компонентов ≤ 2.
</details>

<details>
<summary>2. Почему `build_calldata` стал проще?</summary>

- **A. (верно)** Он теперь `selector ++ encode_sequence(...)` — вся раскладка
  head/tail (и для кортежей, и для аргументов) в одном рекурсивном ядре.
- **B.** Убрали поддержку динамических типов.
- **C.** Перешли на alloy.
</details>

<details>
<summary>3. Как делятся значения `(0xAddr,(1,2))`?</summary>

- **A. (верно)** `split_top_level` считает глубину по `()`/`[]`, поэтому вложенный
  `(1,2)` не режется по внутренней запятой → `["0xAddr","(1,2)"]`.
- **B.** По каждой запятой → 3 части.
- **C.** Только через JSON.
</details>

<details>
<summary>4. Почему прежние тесты не сломались после рефактора?</summary>

- **A. (верно)** Листья рекурсии (скаляр/массивы/bytes/string) кодируются теми же
  функциями, а раскладка head/tail эквивалентна прежней — golden‑тесты это
  фиксируют.
- **B.** Тесты удалили.
- **C.** Случайно.
</details>

<details>
<summary>5. Что с массивами кортежей `(uint256)[]`?</summary>

- **A. (верно)** Пока не поддержаны — внятная ошибка «arrays of tuples not yet
  supported»; редкий случай для mint.
- **B.** Кодируются как `bytes`.
- **C.** Паникуют.
</details>
