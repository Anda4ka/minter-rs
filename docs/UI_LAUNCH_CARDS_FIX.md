# Пояснительная записка: карточки «Launch» на Home — CTA больше не вылезает

Пояснительная записка к PR по UI‑полировке домашнего экрана десктопа
(`crates/minter-desktop/ui`). Задача: добавить иконки в две пусковые карточки
(«OpenSea Mint» и «Raw / MintBay») и починить баг, из‑за которого ссылка‑CTA
(«Open Tasks →» / «Open Raw Mint →») **вылезала за нижнюю границу карточки**.

---

## Background

### Совсем с нуля (можно пропустить, если знаете CSS Grid/Flexbox)

Десктоп MINTER — это приложение на Tauri: нативное окно, внутри которого
крутится обычная веб‑страница (`ui/index.html` + `ui/styles.css`). Всё, что
видит оператор, — это HTML, разложенный двумя механизмами раскладки CSS:

> **Grid vs Flexbox (в двух словах).**
> **Grid** раскладывает элементы по строкам и колонкам таблицы. Ячейка (трек)
> имеет высоту, и по умолчанию элемент в ней *растягивается* на всю высоту строки
> (`align-items: stretch`). **Flexbox** выкладывает детей в одну линию — у нас
> `flex-direction: column`, то есть сверху вниз. Свойство `flex: 1` на ребёнке
> означает «займи всё свободное место по главной оси», и это классический приём,
> чтобы «прижать» последний элемент к низу.

### Узкий контекст: как устроены карточки Launch

На Home есть секция «Launch» — сетка из двух карточек:

```html
<div class="home-launch-grid">
  <button class="home-launch-card card-os">
    <span class="hl-badge">OpenSea</span>
    <span class="hl-title">OpenSea Mint</span>
    <span class="hl-desc">Tasks, phases, multi-wallet sniper for OpenSea drops</span>
    <span class="hl-cta">Open Tasks →</span>
  </button>
  <button class="home-launch-card card-raw"> … </button>
</div>
```

А стили (до изменения) были такими:

```css
.home-launch-grid { display: grid; grid-template-columns: 1fr 1fr; }
.home-launch-card { display: flex; flex-direction: column; min-height: 140px; }
.home-launch-card .hl-desc { flex: 1; }   /* тянемся, чтобы прижать CTA вниз */
```

Идея понятная: карточка — это флекс‑колонка, описание тянется (`flex: 1`),
поэтому CTA всегда прижат к низу. Высота зафиксирована снизу через
`min-height: 140px`, чтобы карточки выглядели «плотными».

---

## Intuition

Пока в карточке было ровно четыре коротких строки, всё влезало в 140px и CTA
спокойно сидел внизу. Но как только сверху добавили **иконку**, содержимое
стало выше карточки — и CTA выехал за нижнюю границу.

Ключевой (и неочевидный) момент: карточка **не выросла** под новый контент. Замер
в браузере показал, что у неё вычисленная `height: 140px` — *фиксированная*, а не
`auto`. Откуда она взялась, если в CSS только `min-height`?

> **Суть бага.** Карточка — элемент грида. При `align-items: stretch` (значение
> по умолчанию) высота карточки приравнивается к высоте строки грида. А строка
> `auto` считает свой размер по «intrinsic size» флекс‑контейнера — и из‑за
> `.hl-desc { flex: 1 }` (flex‑basis `0`) флекс‑колонка сообщает гриду
> *схлопнутую* высоту. В итоге трек берёт максимум из этой мелочи и `min-height`,
> то есть ровно 140px, и делает высоту карточки **definite**. Контент выше 140px
> просто переполняет коробку — CTA уезжает за край.

На игрушечных цифрах: контент с иконкой ≈ 144px, коробка жёстко 140px →
переполнение ≈ 4px при ширине 1280. А на узком окне (960px) описание
переносится на две строки, контенту нужно ≈ 161px, и CTA вылезает уже на ≈ 21px.

Чтобы вылечить это по‑настоящему (а не «подобрать высоту, чтобы влезло»), нужно
две вещи: (1) разрешить карточке расти под контент и (2) заставить флекс‑колонку
честно сообщать свою высоту гриду.

## Code

Все изменения — в двух файлах UI. Логика на Rust не затронута.

**1. `index.html` — иконка первым ребёнком каждой карточки** (в стиле уже
существующих `nav-ico`: тот же `viewBox`, `fill="currentColor"`):

```html
<button class="home-launch-card card-os">
  <span class="hl-ico" aria-hidden="true"><svg viewBox="0 0 24 24" …>…</svg></span>
  <span class="hl-badge">OpenSea</span>
  …
</button>
```

**2. `styles.css` — раскладка, которая растёт под контент:**

```css
.home-launch-grid {
  /* карточка размерится по собственному контенту, а не растягивается
     на фиксированную высоту строки; иначе иконка её переполняет */
  align-items: start;
}

.home-launch-card {
  min-height: 150px;   /* «пол» для коротких карточек */
  height: auto;        /* но разрешаем расти под контент */
}

.home-launch-card .hl-desc {
  flex: 0 0 auto;      /* было flex: 1 — теперь отдаём гриду реальную высоту */
}

.home-launch-card .hl-cta { margin-top: 6px; }
```

**3. `styles.css` — стиль иконок с акцентными цветами под каждую карточку:**

```css
.home-launch-card .hl-ico { display: inline-flex; margin-bottom: 2px; color: var(--muted-2); }
.home-launch-card.card-os  .hl-ico { color: var(--accent-border); } /* фиолетовый */
.home-launch-card.card-raw .hl-ico { color: var(--red); }           /* красный */
```

Почему именно `align-items: start` **и** `height: auto` вместе: по отдельности ни
одно не помогает — карточка всё равно упирается в фиксированные 140/150px. Только
их сочетание отвязывает высоту карточки от высоты строки грида и даёт ей расти.
А замена `flex: 1 → flex: 0 0 auto` у описания убирает «схлопывание», из‑за
которого грид недооценивал нужную высоту.

### До / После

Скриншоты (before/after на 1280 и 960px) приложены в тред ревью/чата — в репозиторий
не коммичу, т.к. `*.png` в `.gitignore`. Кратко: **до** — CTA («Open Tasks →» /
«Open Raw Mint →») прижат к самому краю и обрезается снизу; **после** — CTA с
отступом внутри, иконки на месте, а на узком окне карточки одинаково подрастают
под двухстрочное описание. Числовые замеры — в разделе Verification ниже.

---

## Verification

Проверял не «на глаз», а **замером координат** в headless‑Chromium (Playwright):
для каждой карточки сравнивал `getBoundingClientRect().bottom` у CTA и у самой
карточки (`ctaOutside = ctaBottom > cardBottom`).

| Сценарий (с иконкой) | Ширина | До: запас под CTA | До: вылез? | После: запас | После: вылез? |
|---|---|---|---|---|---|
| Обычный | 1280px | −4px | **да** | +23px | нет |
| Узкое окно (2 колонки) | 960px | −21px | **да** | +23px | нет |
| Одна колонка | 780px | — | — | +23px | нет |
| Длинное описание (стресс) | 960px | −11px | **да** | +23px | нет |

Отдельно проверил, что карточка теперь **растёт**: 168px → 185px (перенос на 2
строки) → 202px (искусственно длинный текст) — во всех случаях CTA внутри.

Как проверить вручную:

1. Собрать/запустить десктоп (`cargo tauri dev` из `crates/minter-desktop`), либо
   открыть `crates/minter-desktop/ui/index.html` в браузере и через DevTools снять
   `hidden` с `#view-main` / `#page-home`.
2. Открыть Home → секция «Launch».
3. Проверить, что у обеих карточек слева‑сверху есть иконка (фиолетовая у OpenSea,
   красная у Contract), а ссылка «Open … →» с отступом внутри карточки.
4. Потянуть окно к минимальной ширине — описание переносится, карточки растут,
   CTA остаётся внутри.

> **Замечание про кодировку.** В `styles.css` в комментариях остались 5 «битых»
> байтов `0x97` (Windows‑1252 тире) из прошлых правок. Я их **намеренно не трогал**,
> чтобы не расширять диффф; правил файл побайтово (latin‑1 round‑trip). Это
> латентная мелочь в комментариях, кандидат на отдельную зачистку.

## Alternatives

**Альтернатива A — просто поднять `min-height` (например, до 168px).**

| Плюсы | Минусы |
|---|---|
| Минимальный дифф (одна строка) | Не лечит причину: карточка всё равно не растёт |
| Для текущего текста «влезает» | Ломается на длинном тексте/переводах (замер: −11px) |
| Ничего не надо понимать про грид | Пустое место в коротких карточках |

**Альтернатива B — прижать CTA через `margin-top: auto` (вместо `flex` у описания).**

| Плюсы | Минусы |
|---|---|
| CTA красиво прижат к низу, когда есть запас | Сам по себе не чинит переполнение |
| Хорошо сочетается с `align-items: start` | Всё равно нужен `height: auto`, иначе клампится |
| Меньше меняем семантику `.hl-desc` | Разное поведение отступа в коротких/длинных карточках |

Выбранный вариант (`align-items: start` + `height: auto` + `flex: 0 0 auto`)
чинит именно корень и проверен на переполнение при любой ширине.

## Quiz

<details>
<summary>1. Почему карточка не росла под добавленную иконку, хотя в CSS была только <code>min-height</code>?</summary>

- **A.** У `.hl-desc` стоял `overflow: hidden`.
- **B. (верно)** Карточка — элемент грида с `align-items: stretch`, поэтому её
  высота приравнивалась к высоте строки; строка бралась ≈ `min-height` (флекс‑колонка
  из‑за `flex: 1` сообщала гриду схлопнутую высоту), и высота становилась
  *фиксированной*. Контент выше просто переполнял коробку.
- **C.** `min-height` в CSS вообще не работает на кнопках.

`min-height` сам по себе рост разрешает; проблема была в том, что грид навязывал
карточке *definite height*.
</details>

<details>
<summary>2. Почему одного <code>align-items: start</code> не хватило?</summary>

- **A. (верно)** У карточки всё ещё оставалась вычисленная фиксированная высота;
  нужно было явно `height: auto`, чтобы отвязать высоту карточки от трека грида.
- **B.** `align-items` не применяется к grid‑контейнерам.
- **C.** Нужно было убрать `display: flex`.

Замер показывал `height: 140px` даже с `align-items: start` — пока не добавили
`height: auto`.
</details>

<details>
<summary>3. Что делает замена <code>flex: 1</code> → <code>flex: 0 0 auto</code> у <code>.hl-desc</code>?</summary>

- **A.** Центрирует описание.
- **B. (верно)** Убирает flex‑basis `0`/схлопывание, поэтому описание отдаёт свою
  *реальную* высоту при расчёте intrinsic‑размера — грид перестаёт недооценивать
  нужную высоту карточки.
- **C.** Прячет описание при переносе.
</details>

<details>
<summary>4. Как именно проверялась корректность фикса?</summary>

- **A.** Визуально по скриншоту на одной ширине.
- **B. (верно)** Замером `getBoundingClientRect()` CTA и карточки в headless‑Chromium
  на 1280/960/780px и на стресс‑тексте; критерий `ctaBottom > cardBottom`.
- **C.** Юнит‑тестами на Rust.
</details>

<details>
<summary>5. Почему стрелочная (длинная) карточка на 960px стала выше, чем на 1280px?</summary>

- **A. (верно)** На узкой ширине описание переносится на две строки, контента
  становится больше, и благодаря `height: auto` карточка растёт (185px против 168px).
- **B.** Из‑за медиазапроса, который меняет `font-size`.
- **C.** Потому что иконка на 960px крупнее.

Обе карточки растут одинаково, оставаясь равной высоты в пределах строки грида.
</details>
