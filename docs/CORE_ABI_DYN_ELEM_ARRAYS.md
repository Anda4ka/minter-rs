# ABI: массивы динамических элементов (`bytes[]`, `string[]`)

Продолжение пункта **#10** (после Phase A `T[]` статических и Phase B `T[n]`).
Добавлено кодирование динамических массивов **динамических** элементов —
`bytes[]` и `string[]`.

## Background

`bytes[]` — динамический массив, где **каждый элемент** тоже динамический
(своя длина). Такой массив кодируется как «длина + таблица смещений + сами
элементы», где смещения указывают на кодировку каждого элемента.

## Intuition

Раскладка `bytes[]` из `[e0, e1]` (смещения — от начала таблицы смещений, т.е.
сразу после слова длины):

```
[len = 2]
[off0]         // = 2*32 (две ячейки смещений)
[off1]         // = off0 + размер enc(e0)
[enc(e0)]      // [len(e0)] + data, паддинг до 32
[enc(e1)]
```

`enc(bytes)` = слово длины + данные с правым паддингом; `enc(string)` то же для
UTF‑8 байт.

## Code (`abi.rs`)

- `encode_dynamic_element_array(elem_ty, values)` — длина + таблица смещений +
  кодировки элементов (`bytes`/`string`).
- `is_supported_type`: динамический `T[]` теперь ок и для `bytes`/`string`
  (фикс `T[n]` — только статические элементы, как в Phase B).
- `build_calldata`/`encode_parameter`: в динамической ветке выбирают
  static‑array vs dynamic‑element‑array по типу элемента.
- `unsupported_type_error`: осмысленные сообщения для **вложенных** массивов
  (`uint256[][]`), **фикс‑массивов динамических элементов** (`bytes[3]`) и
  **кортежей** (Phase D).

> **Ограничение:** элементы делятся по запятой, поэтому строки `string[]` не
> должны содержать запятых (CSV‑ввод оператора). `bytes[]` (hex) не затронут.

## Verification

`cargo test -p minter-core` → **158 passed** (+2). Golden‑тесты проверяют точную
раскладку `bytes[]` (offset’ы 0x40/0x80, длины и данные элементов) и `string[]`
(«hi»), плюс понятные ошибки для nested/fixed‑dynamic/tuple.

## Quiz

<details>
<summary>1. Чем `bytes[]` сложнее `uint256[]`?</summary>

- **A. (верно)** У `bytes[]` каждый элемент динамический → нужна таблица
  смещений внутри массива; у `uint256[]` элементы — по одному слову, смещения не
  нужны.
- **B.** Ничем.
- **C.** `bytes[]` статический.
</details>

<details>
<summary>2. Относительно чего заданы смещения элементов внутри массива?</summary>

- **A. (верно)** От начала таблицы смещений — т.е. сразу после слова длины.
- **B.** От начала всей calldata.
- **C.** От селектора.
</details>

<details>
<summary>3. Почему `string[]` с запятыми в строках — проблема?</summary>

- **A. (верно)** Значения делятся по запятой, поэтому запятая внутри строки
  сломает разбиение — это задокументированное ограничение CSV‑ввода.
- **B.** UTF‑8 не поддерживается.
- **C.** Строки вообще нельзя.
</details>
