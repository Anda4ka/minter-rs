# Пояснительная записка: исправления по код-аудиту

Пояснительная записка к PR с исправлениями, найденными при код-ревью репозитория
`Anda4ka/minter-rs` (Rust: ядро `minter-core` + десктоп на Tauri `minter-desktop`).

## Background

**Для тех, кто видит проект впервые.** MINTER — это десктопное приложение для
«снайпинга» NFT-минтов. Пользователь импортирует набор burner-кошельков
(приватные ключи хранятся в зашифрованном `keys.vault`), выбирает дроп (на
OpenSea или напрямую по адресу контракта) и в нужный момент рассылает
транзакции минта сразу с многих кошельков. Логика разбита на два крейта:
`minter-core` (вся бизнес-логика, без UI) и `minter-desktop` (тонкая обёртка
Tauri, пробрасывающая команды из webview в ядро).

Ключевые модули ядра: `rpc.rs` (JSON-RPC клиент с фейловером по нескольким
нодам), `opensea.rs` (SIWE-аутентификация и GraphQL для получения calldata
минта), `raw_mint.rs` / `raw_sniper.rs` (минт напрямую по контракту, в т.ч.
пресайн-гонка по часам), `flashbots.rs` (приватные бандлы для mainnet),
`sign.rs` (подпись EIP-1559), `vault.rs` / `settings.rs` (шифрованное хранилище
ключей и конфиг).

**Узкий контекст этого изменения.** В прошлом коммите
(`audit: fix wrong mint selectors, Flashbots auth signature, and panic paths`)
уже чинили часть «панических» путей — например, `rpc::short_url` и
`proxy::short_proxy` были переписаны с байтовой нарезки строк на посимвольную.
Но тот же самый паттерн обрезки строк остался в доброй дюжине других мест, плюс
всплыл ряд менее заметных дефектов в конкурентности команд, обработке ответа
OpenSea и хранении секретов. Этот PR закрывает именно их.

## Intuition

Основная идея почти всех правок — **не падать и не отправлять некорректную
транзакцию на «граничных» данных**, которые приходят извне (тело HTTP-ответа
RPC/OpenSea, значение `value` из GraphQL, цена фазы из контракта).

> ⚠️ **Ключевой факт про Rust:** `&s[..n]` для `String` режет по **байтовому**
> индексу. Если `n` попадает в середину многобайтового UTF-8 символа — это
> `panic`, а не просто обрезка. Строка `"ошибка"` занимает 12 байт при 6
> символах, поэтому `&s[..5]` паникует.

Тойный пример: RPC-нода вернула HTTP 500 с телом на кириллице
`"внутренняя ошибка сервера…"`. Старый код делал `&text[..text.len().min(240)]`.
Если байт №240 попал в середину буквы — приложение падало прямо в обработчике
ошибки, то есть падало *вместо* того, чтобы показать ошибку. Новый помощник
`safe_truncate` откатывается назад до ближайшей границы символа.

Вторая идея — **один кошелёк не должен одновременно слать две транзакции**. У
EVM-транзакции есть `nonce`; две параллельные операции с одним nonce конфликтуют
(одна вытеснит другую или зависнет). В десктопе только `run_mint` и `raw_sniper`
держали флаг «идёт операция», а `raw_mint`/`disperse`/`multicall`/`sweep_*` —
нет, поэтому их можно было запустить поверх работающего минта.

## Code

**1. Помощник `safe_truncate` (`lib.rs`).** Единая точка безопасной обрезки,
используется во всех местах логирования/ошибок вместо `&text[..…]`.

```rust
pub fn safe_truncate(s: &str, max_bytes: usize) -> &str {
    if s.len() <= max_bytes { return s; }
    let mut end = max_bytes;
    while end > 0 && !s.is_char_boundary(end) { end -= 1; }
    &s[..end]
}
```

Заменены все опасные срезы в `rpc.rs` (4×), `opensea.rs` (5×), `flashbots.rs`
(2×), `sweep.rs` (1×). Единственный оставшийся `&short[..8]` в `rpc.rs`
безопасен — там `short` это hex (гарантированно ASCII).

**2. Общий гейт конкурентности (`minter-desktop/src-tauri/src/lib.rs`).**
`raw_mint`, `disperse`, `multicall`, `sweep_eth`, `sweep_nfts` теперь берут тот
же флаг `mint_running`, что и `run_mint`:

```rust
if state.mint_running.swap(true, Ordering::SeqCst) {
    return Err(minter_core::mint_busy_message().into());
}
let result = session.raw_mint(/* … */).await.map_err(|e| e.to_string());
state.mint_running.store(false, Ordering::SeqCst);
result
```

Между `swap` и `store` нет `?`, поэтому флаг снимается при любом исходе (Ok/Err).

**3. OpenSea `value` как число (`opensea.rs`).** `transactionSubmissionData.value`
мог прийти JSON-числом; старый `as_str()` давал `None` → значение `0x0` → минт с
нулевой оплатой и реверт. Теперь принимаются и строка, и число:

```rust
let value = match value_val {
    Some(v) if v.is_string() => v.as_str().unwrap_or("0x0").to_string(),
    Some(v) if v.is_u64()    => v.as_u64().unwrap_or(0).to_string(),
    Some(v) if v.is_number() => v.to_string(),
    _ => "0x0".to_string(),
};
```

**4. Цена MintBay в фолбэке (`raw_sniper.rs`).** Когда `getMintStatus` не
отвечает и используется fallback по отдельным view-вызовам, поля цены остаются
нулевыми. Раньше Auto-режим слал `value`, равный только `collector_fee` →
недоплата. Теперь если цена неизвестна, а у пользователя задан `fixed_value` —
берётся он:

```rust
let price_known = !st.public_mint_price.is_zero() || !st.phase_mint_price.is_zero();
if !price_known && !config.fixed_value.is_zero() {
    (config.fixed_value, "MintBay auto: price unavailable — using fixed …")
} else { /* обычный расчёт st.mint_value(qty) */ }
```

**5. Права на `config.json` (`settings.rs`).** Конфиг хранит ключ Alchemy
открытым текстом; на unix временный файл теперь создаётся с правами `0o600` —
как и у vault.

**6. Насыщающее преобразование комиссий (`sign.rs`).** `max_fee.to::<u128>()`
паникует при переполнении; заменено на `saturating_to::<u128>()`.

**7. Макрос `rprint!` (`lib.rs`, `raw_mint.rs`, `multicall.rs`).** Частичные
строки `"Simulating…/Sending…/Receipt…"` печатались через сырой `print!` в обход
`QUIET=1` (дефолт десктопа). Новый `rprint!` уважает `QUIET` и делает `flush`.

**Ручная проверка (QA):**
1. RPC-панику проще всего проверить юнит-тестом `safe_truncate`, либо направив
   приложение на RPC-URL, отдающий не-ASCII тело ошибки — приложение должно
   показать усечённую ошибку, а не крашнуться.
2. Конкурентность: запустите `run_mint` (можно dry-run с `at_time` в будущем),
   затем во время ожидания нажмите Sweep/Disperse/Raw Mint — должно вернуться
   сообщение «busy», а не запуститься второй поток.
3. OpenSea `value`: dry-run минт платного дропа — в логе `PREPARED … value=<ненулевое>`,
   значение совпадает с ценой фазы.
4. `config.json`: на unix после сохранения настроек `ls -l config.json` →
   `-rw-------`.

## Alternatives

**Обрезка строк.** Вместо помощника `safe_truncate` можно было везде
использовать `s.chars().take(n).collect::<String>()`.

| Плюсы | Минусы |
| --- | --- |
| Не нужен отдельный helper | Аллоцирует новую `String` на каждый вызов |
| Ограничение по символам, а не байтам | «240» перестаёт означать предел размера лога в байтах |
| Привычная идиома | Дублируется по всем call-site, легко снова забыть |

**Гейт конкурентности.** Вместо переиспользования одного `mint_running` можно
было завести отдельный per-operation мьютекс или очередь задач.

| Плюсы | Минусы |
| --- | --- |
| Разные операции могли бы идти параллельно на разных кошельках | Сложнее: нужна привязка блокировки к набору адресов |
| Точнее отражает реальный конфликт (по nonce) | Легко ошибиться и всё равно словить гонку nonce |
| — | Избыточно для текущего UX (одна активная операция) |

## Quiz

<details>
<summary>1. Почему <code>&text[..text.len().min(240)]</code> может паниковать?</summary>

- **А. Индекс выходит за длину строки** — неверно: `.min(240)` гарантирует ≤ длины.
- **Б. Срез по байту может попасть в середину UTF-8 символа** — ✅ верно: `String`
  режется по байтам, и не-ASCII символ занимает 2–4 байта.
- **В. `text` может быть пустым** — неверно: пустая строка режется в пустую без паники.

</details>

<details>
<summary>2. Что произойдёт с флагом <code>mint_running</code>, если гарантированная операция вернёт ошибку?</summary>

- **А. Останется `true` навсегда** — неверно.
- **Б. Снимется в `false`, потому что между `swap` и `store` нет раннего возврата (`?`)** — ✅ верно.
- **В. Снимется только при `Ok`** — неверно: результат сохраняется в переменную,
  флаг снимается до `return`.

</details>

<details>
<summary>3. Чем грозил разбор <code>value</code> из OpenSea только через <code>as_str()</code>?</summary>

- **А. Ничем, OpenSea всегда шлёт строку** — неверно/небезопасно: поле бывает числом.
- **Б. Числовое значение превращалось в `0x0` → минт с нулевой оплатой → реверт** — ✅ верно.
- **В. Падение приложения** — неверно: был тихий дефолт `0x0`, без паники.

</details>

<details>
<summary>4. Почему в фолбэке MintBay Auto-режим мог недоплатить?</summary>

- **А. `getMintStatus` возвращал завышенную цену** — неверно.
- **Б. View-фолбэк не читает цену, поля остаются 0, и `value` считался как один `collector_fee`** — ✅ верно.
- **В. Ошибка округления в U256** — неверно: арифметика точная (saturating).

</details>

<details>
<summary>5. Зачем понадобился <code>rprint!</code> вместо <code>print!</code>?</summary>

- **А. `print!` не делает flush** — частично, но не главное.
- **Б. Сырой `print!` игнорировал `QUIET=1` и «протекал» в stdout в десктопе** — ✅ верно (плюс `rprint!` ещё и делает flush).
- **В. `print!` медленнее** — неверно.

</details>
