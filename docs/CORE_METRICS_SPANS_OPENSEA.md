# #9 — пофазные спаны в OpenSea‑ране (шаг 2)

Второй шаг проводки #9: заполняет пофазные спаны `RunMetrics` (auth / nonce /
wait) и open‑signal реальными длительностями. **Черновик для ревью** — касается
`run_opensea_mint`, мержим после просмотра.

> Продолжение шага 1 (сборка `RunMetrics` из результатов). Теперь у метрик
> появляются длительности последовательных фаз и лаг открытия.

## Intuition

Не тащим состояние через конкурентный цикл отправки (там риск). Вместо этого
измеряем **последовательные фазы** локальными `Instant` прямо в теле функции и
складываем в коллектор на финализации:

```
auth:  Instant перед авторизацией → длительность после join всех SIWE‑задач
nonce: Instant перед refresh нонсов → длительность после join
wait:  Instant в начале ожидания открытия → длительность в момент "Phase is open!"
       + open_signal { kind:"wall_clock", open_ts:start_ts, fire_lag_ms }
```

`auth`/`nonce` выполняются всегда (обычные `let`‑длительности); `wait` — только в
режиме таймера открытия (`Option`, потому что фаза может отсутствовать).

## Code (`mint.rs`)

- Объявлены `span_wait_ms: Option<u64>` и `open_signal_meta` в начале функции.
- Три пары «Instant до фазы → длительность после»: вокруг блока SIWE‑авторизации,
  вокруг refresh нонсов, вокруг ожидания открытия.
- На финализации (в существующем блоке `do_export`, шаг 1):
  `collector.mark_span("auth"/"nonce"/"wait", …)` + `set_open_signal(...)` перед
  `finish()`.

Никаких изменений в управляющем потоке и в горячем цикле отправки/подтверждения.

## Границы (следующие шаги)

- `first_send_ack_ms` / `first_confirm_ms` — это **offset’ы** первого ack/confirm;
  они происходят внутри конкурентных задач, поэтому требуют аккуратного
  once‑захвата в общий коллектор. Отдельный шаг.
- Raw‑путь и History UI — отдельно.
