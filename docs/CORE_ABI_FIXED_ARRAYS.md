# ABI: фиксированные массивы статических элементов (`T[n]`)

Продолжение пункта **#10** (после Phase A — динамические `T[]`). Добавлено
кодирование фиксированных массивов статических элементов: `uint256[3]`,
`address[2]`, `bytes32[4]`, `bool[2]` и т.п.

## Background

`T[n]` со статическим элементом — сам по себе **статический** тип: занимает `n`
слов **в голове**, без слова длины и без offset (в отличие от динамического
`T[]`). Проблема была в `build_calldata`: `head_size = n_args * 32` предполагал
ровно одно слово на аргумент, что ломает layout при фиксированных массивах.

## Intuition

Считаем размер головы **по типам**: динамический → 1 слово (offset), фиксированный
`T[n]` статический → `n` слов, остальное → 1 слово. Тогда offset’ы динамических
частей остаются верными, а `T[n]` просто раскладывается инлайн.

Игрушечный пример `f(address[2], uint256[])`: голова = 2 (фикс) + 1 (offset) = 3
слова = 96 байт, поэтому offset динамического массива = `0x60`.

## Code (`abi.rs`)

- `encode_static_array_fixed(elem, values, n)` — ровно `n` слов, без длины; ошибка
  при несовпадении количества.
- `head_word_bytes(ty)` — вклад типа в голову (1 слово / `n` слов / offset).
- `build_calldata`: `head_size = Σ head_word_bytes(t)`; ветка фиксированного
  массива кладёт `n` слов инлайн.
- `is_supported_type` теперь принимает `T[n]` со статическим элементом;
  `unsupported_type_error` оставляет ошибки только для dynamic‑element массивов
  (`bytes[]`/`string[]`, Phase C) и кортежей (Phase D).

> **Границы:** dynamic‑element массивы и кортежи по‑прежнему дают понятную ошибку.

## Verification

`cargo test -p minter-core` → **156 passed** (+3). Тесты: `uint256[3]` инлайн,
смешанный `g(uint256[2],uint256)`, **`f(address[2],uint256[])` с offset = 0x60**,
ошибка при неверном количестве элементов.

## Quiz

<details>
<summary>1. Почему `T[n]` статический, а `T[]` динамический?</summary>

- **A. (верно)** У `T[n]` длина известна из типа → `n` слов инлайн в голове; у
  `T[]` длина в рантайме → offset + `len` + элементы в хвосте.
- **B.** Оба динамические.
- **C.** Зависит от элемента.
</details>

<details>
<summary>2. Что чинит `head_word_bytes`?</summary>

- **A. (верно)** Голова больше не `n_args*32`: фиксированный `T[n]` вносит `n`
  слов, поэтому offset’ы динамических частей считаются корректно.
- **B.** Ускоряет кодирование.
- **C.** Валидирует адреса.
</details>

<details>
<summary>3. Что будет при `uint256[3]` с двумя значениями?</summary>

- **A. (верно)** Ошибка «expects 3 element(s), got 2».
- **B.** Допишется нулём.
- **C.** Возьмёт первые 2.
</details>
